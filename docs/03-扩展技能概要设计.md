## 一、架构总览

### 1.1 扩展后的 Agent 层架构

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 展示层    CLI │ Streamlit 面板 │ Markdown 周报 │ 邮件/webhook │
├─────────────────────────────────────────────────────────────────────────────┤
│ Agent 层(crewAI Crew,业务编排)                                              │
│   Scout(搜集) → Parser(结构化) → Matcher(评分+证据链) → Reporter(报告+建议) │
│                          ↑                           ↑                      │
│                   Claim Extractor            Gap Advisor │ Interview Prep   │
│                   (嵌入 Matcher)            (嵌入 Reporter 的两个子任务)    │
├─────────────────────────────────────────────────────────────────────────────┤
│ 工具层    ats_collector(GH/Lever) │ researcher_tool │ browser_tool(二期)    │
│           db_tool │ notify_tool │ claim_tool │ gap_tool │ interview_tool    │
├─────────────────────────────────────────────────────────────────────────────┤
│ 网关层    LLM Gateway(自写薄层):GLM 接入统一封装、Schema 校验+重试、         │
│           结果缓存、token/费用计量                                           │
├─────────────────────────────────────────────────────────────────────────────┤
│ 存储层    SQLite(职位/评分/报告/Claim/Gap/InterviewBrief/成本流水)           │
│           profile.yaml + resume.md                                          │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 1.2 数据流变化

**原有流程（M1-M4）**：
```
JD 原文 → Parser(结构化) → Matcher(评分) → MatchScore → Reporter(周报)
```

**扩展后流程（M5+）**：
```
JD 原文 → Parser(结构化) → Matcher(评分+Claim提取) → MatchScore + ClaimExtractionResult
                                                            ↓
                                                    Reporter(Gap分析+建议生成)
                                                            ↓
                                            ResumePatch + InterviewBrief → 周报
```

### 2.1 Claim Evidence Extractor（嵌入 Matcher）

#### 2.1.1 模块结构

```
└── prompts/
    └── claim_extraction.py       # 新增，Claim 提取 prompt 模板
```

#### 2.1.2 与 Matcher 的集成方式

```python
# 伪代码示意
class MatcherAgent:
    def evaluate(self, job_posting: JobPosting, profile: Profile) -> MatchScore:
        # 原有逻辑：评分
        score = self._score_job(job_posting, profile)

        # 新增逻辑：Claim 提取（复用 JD 解析结果）
        claims = self.claim_extractor.extract(
            resume=profile.resume_md,
            jd_text=job_posting.raw_text,
            parsed_jd=job_posting.parsed_jd  # 来自 Parser
        )

        # 合并到 MatchScore
        score.claims = claims.claims
        score.gaps = claims.gaps
        score.evidence_matrix = claims.evidence_matrix

        return score
```

#### 2.1.3 核心算法

1. **Claim 提取**：从简历文本中识别可验证声明，按 5 类分类
2. **JD 映射**：将每个 Claim 与 JD 要求进行语义匹配
3. **Gap 检测**：识别 JD 要求中无 Claim 覆盖的部分，分类为 hard_block/soft_gap
4. **缓存策略**：hash(JD 内容 + 简历版本) → 命中则跳过提取

### 2.2 Resume Gap Advisor（嵌入 Reporter）

#### 2.2.1 模块结构

```
src/jobpilot/
├── agents/
│   └── reporter_agent.py         # 现有，扩展 prompt
├── tools/
│   └── gap_advisor_tool.py       # 新增，Gap 分析与建议生成工具
├── models/
│   └── resume_patch.py           # 新增，BulletRewrite/HROpener/ResumePatch 数据模型
└── prompts/

```

#### 2.2.2 与 Reporter 的集成方式

```python
# 伪代码示意
class ReporterAgent:
    def generate_weekly_report(self, match_scores: list[MatchScore]) -> Report:
        # 原有逻辑：生成周报主体
        report_body = self._generate_report_body(match_scores)

        # 新增逻辑：对 Top N 高分职位生成建议
        top_n_scores = sorted(match_scores, key=lambda s: s.overall, reverse=True)[:10]
        resume_patches = []

        for score in top_n_scores:
            if score.overall >= 70:  # 触发阈值
                patch = self.gap_advisor.generate_patch(
                    claims=score.claims,
                    gaps=score.gaps,
                    job_posting=score.job_posting,
                    profile=self.profile
                )
                resume_patches.append(patch)

        # 合并到周报
        report = Report(
            body=report_body,
            resume_patches=resume_patches,  # 新增章节
            ...
        )

        return report
```

#### 2.2.3 核心算法

1. **Bullet 改写**：基于 Gap 的 jd_requirement，改写简历中相关经历的表述
2. **缺失证据建议**：对 soft_gap 生成"建议补充 XX 项目/经历"的具体建议
3. **HR 开场白**：提取与职位最相关的 2-3 个 Claim，生成一段话开场白
4. **ResumePatch 输出**：Markdown 格式，可直接合并到简历

### 2.3 Interview Prep Generator（Reporter 子任务）

#### 2.3.1 模块结构

```
src/jobpilot/
├── agents/
│   └── reporter_agent.py         # 现有，扩展 prompt
├── tools/
│   └── interview_prep_tool.py    # 新增，面试预测工具
├── models/
│   └── interview_brief.py        # 新增，PredictedQuestion/FollowUp/InterviewBrief 数据模型
└── prompts/
    └── interview_prep.py         # 新增，面试预测 prompt 模板
```

#### 2.3.2 与 Reporter 的集成方式

```python
# 伪代码示意
class ReporterAgent:
    def generate_weekly_report(self, match_scores: list[MatchScore]) -> Report:
        # ... 原有逻辑 + Gap Advisor ...

        # 新增逻辑：对 Top N 高分职位生成面试准备
        top_5_scores = sorted(match_scores, key=lambda s: s.overall, reverse=True)[:5]
        interview_briefs = []

        for score in top_5_scores:
            # 复用 Researcher Agent 的公司调研
            company_research = self.researcher.research(score.job_posting.company)

            brief = self.interview_prep.generate_brief(
                claims=score.claims,
                gaps=score.gaps,
                job_posting=score.job_posting,
                company_research=company_research,
                profile=self.profile
            )
            interview_briefs.append(brief)

        # 合并到周报
        report = Report(
            body=report_body,
            resume_patches=resume_patches,
            interview_briefs=interview_briefs,  # 新增章节
            ...
        )

        return report
```

#### 2.3.3 核心算法

1. **问题预测**：基于 JD 明确要求 + Claim 类型，生成高频面试问题
2. **追问协议**：每个问题生成 2-3 个追问，设计检测目标和危险信号
3. **弱项练习**：对 strength=weak/missing 的 Claim 生成专项练习题
4. **面试速览**：整合公司调研 + 技术栈 + 预测题 + 证据摘要，输出一页纸 Markdown

## 三、数据模型扩展

### 3.1 新增表结构

```sql
-- Claim 提取结果
CREATE TABLE claim_extractions (
    id TEXT PRIMARY KEY,
    job_id TEXT NOT NULL,
    resume_version TEXT NOT NULL,
    claims_json TEXT NOT NULL,      -- Claim[]
    gaps_json TEXT NOT NULL,        -- Gap[]
    evidence_matrix_json TEXT,      -- map<claim_id, map<jd_req_id, status>>
    extraction_tokens INTEGER,
    extraction_cost REAL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (job_id) REFERENCES job_postings(id)
);

-- Resume Patch
CREATE TABLE resume_patches (
    id TEXT PRIMARY KEY,
    job_id TEXT NOT NULL,
    bullet_rewrites_json TEXT,      -- BulletRewrite[]
    missing_evidence_json TEXT,     -- MissingEvidence[]
    hr_opener_text TEXT,
    patch_markdown TEXT,
    generation_tokens INTEGER,
    generation_cost REAL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (job_id) REFERENCES job_postings(id)
);

-- Interview Brief
CREATE TABLE interview_briefs (
    id TEXT PRIMARY KEY,
    job_id TEXT NOT NULL,
    company_overview TEXT,
    tech_stack_json TEXT,           -- str[]
    predicted_questions_json TEXT,  -- PredictedQuestion[]
    followup_protocol_json TEXT,    -- FollowUp[]
    weak_area_drills_json TEXT,     -- WeakAreaDrill[]
    evidence_summary_json TEXT,     -- map<claim_type, Claim[]>
    brief_markdown TEXT,
    generation_tokens INTEGER,
    generation_cost REAL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (job_id) REFERENCES job_postings(id)
);
```

## 四、Prompt 设计

### 4.1 Claim 提取 Prompt 模板

```
你是一个简历证据分析专家。请从以下简历文本中提取可验证声明（Claim）。

## 简历文本
{resume_text}

## JD 要求（已结构化）
{parsed_jd_json}

## 任务
1. 提取简历中所有可验证声明
2. 每个 Claim 分类为以下 5 类之一：
   - Ownership：表明个人负责/主导某项工作
   - Metric：包含可量化的指标（数字、百分比、规模）
   - Technical：展示技术能力或工具使用
   - Architecture：展示系统设计或架构决策
   - Result：展示成果或影响
3. 将每个 Claim 与 JD 要求进行匹配
4. 识别 JD 要求中无 Claim 覆盖的部分（Gap）

## 输出格式（JSON）
{
  "claims": [
    {
      "claim_type": "Metric",
      "claim_text": "将 API 响应时间从 2s 优化到 200ms",
      "resume_span": {"start": 120, "end": 150, "text": "..."},
      "jd_evidence": "要求有性能优化经验",
      "jd_span": {"start": 500, "end": 520, "text": "..."},
      "strength": "strong"
    }
  ],
  "gaps": [
    {
      "gap_type": "soft_gap",
      "jd_requirement": "熟悉 Kubernetes",
      "related_claims": [],
      "mitigation": "建议补充一个 K8s 相关项目或学习经历"
    }
  ]
}
```

## 五、缓存与成本控制

### 5.1 缓存策略

| 技能 | 缓存键 | 缓存失效条件 |
|------|--------|-------------|
| Claim Extractor | hash(JD 内容 + 简历版本) | JD 更新或简历版本变更 |
| Gap Advisor | hash(JD 内容 + 简历版本 + Claim 结果) | Claim 结果变更 |
| Interview Prep | hash(JD 内容 + 简历版本 + 公司调研) | 公司调研更新 |

### 5.2 触发控制

| 技能 | 触发条件 | 批量策略 |
|------|----------|----------|
| Claim Extractor | 每条新 JD 评分时 | 可与评分合并为一次 LLM 调用 |
| Gap Advisor | MatchScore.overall ≥ 70 | Top 10 批量处理 |
| Interview Prep | MatchScore.overall ≥ 70 | Top 5 批量处理 |

### 5.3 成本归因

每个技能的 LLM 调用独立计量，写入对应表的 `*_tokens` 和 `*_cost` 字段，汇总到周报的"成本报告"章节。

| 场景 | 验证点 |
|------|--------|

### 6.3 评测指标

| 指标 | 目标 | 评测方法 |

| Claim 分类准确率 | ≥ 85% | 50 条人工标注 |

| 改写建议可用性 | ≥ 90% | 用户反馈"可直接使用" |
