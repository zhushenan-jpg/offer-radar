## 2. llm_gateway(核心,最先做)

### 2.1 接口签名

```python
class GatewayConfig(BaseSettings):
    model: str = "glm-5.3-flash"
    base_url: str
    api_key: SecretStr
    temperature: float = 1.0
    top_p: float = 0.95
    max_retries: int = 3
    timeout_s: float = 120
    monthly_budget_cny: float = 30.0
    price_input_cny_per_mtok: float = 4.0  # 实测后校准;错峰半价由调度层体现
    price_output_cny_per_mtok: float = 21.0


class LLMGateway:
    def __init__(self, cfg: GatewayConfig, db: Storage): ...
    def json_in(
        self,
        schema: type[T],
        prompt: str,
        *,
        system: str = "",
        cache_key: str | None = None,
        module: str = "",
    ) -> T:
        """结构化输出主入口。流程:
        1) cache_key 命中缓存 → 直接反序列化返回,记 cache_hit=1
        2) instructor.chat.completions.create(response_model=schema)
           失败重试 max_retries 次(校验错误回喂)
        3) 成功 → metering 落库 → 返回 pydantic 实例
        4) 3 次仍失败 → raise GatewaySchemaError(附原始文本)"""

    def text(self, prompt: str, *, system: str = "", module: str = "") -> str: ...
    def budget_check(self) -> None:
        """月累计 cost_cny 超 monthly_budget_cny → raise BudgetExceeded"""
```

### 2.2 设计决策

| 决策 | 方案 | 理由/回退 |
|---|---|---|
| 结构化输出通道 | instructor 默认(json schema → tool-call);失败回退"prompt 要求纯 JSON + pydantic 解析" | GLM 兼容层对 response_format 支持度待实测,两条腿走路 |
| reasoning_content | 剥离并忽略(仅日志保留前 200 字符) | thinking 恒开,不剥离会污染解析 |
| 缓存 | SQLite 表 `llm_cache(key PK, value_json, created_at)`;key=sha256(schema名+prompt+model+相关版本号) | 评分缓存失效依赖 rubric_version/resume_version |
| 计量 | 每次(含 cache miss 重试)写 `usage` 表:module/model/prompt_tokens/completion_tokens/cost_cny/cache_hit | 成本归因到模块,周报展示 |
| 预算 | `budget_check()` 在每次网关调用前执行 | 硬保险,超限即停跑并通知 |

## 3. 数据模型(pydantic v2)

```python
class Evidence(BaseModel):
    dim: Literal["skills", "experience", "constraints", "growth"]
    quote: str          # JD 原文片段,≤50 字
    reason: str

class DimScore(BaseModel):
    score: int          # 0-10
    evidence: list[Evidence]   # ≥1 条

class MatchScore(BaseModel):
    overall: float      # 0-100,= Σ(w_i × dim_i) × 10,校验一致性
    dims: dict[Literal[...4维...], DimScore]
    confidence: float   # 0-1,模型自评
    summary: str        # ≤80 字中文理由

class JobPosting(BaseModel):
    id: str             # sha1(source|company|norm_title|location)[:16]
    source: Literal["greenhouse", "lever"]
    company: str; title: str; location: str; remote: bool
    url: str; department: str; description_md: str
    first_seen: datetime; last_seen: datetime
    status: Literal["new", "parsed", "scored", "review", "error", "archived"]

class Profile(BaseModel):
    name: str; skills: list[str]; years: float
    education: str; resume_md: str; resume_version: str  # = sha1(resume_md)[:12]
    desired: Desired{roles, cities, remote_ok, salary_range, keywords_exclude}
```

## 4. collectors

```python
class Collector(ABC):
    source: str
    async def fetch(self, slug: str) -> list[RawJob]:  # httpx.AsyncClient
    def normalize(self, raw: RawJob, company: str) -> JobPosting
```

| | Greenhouse | Lever |
|---|---|---|
| URL | `boards-api.greenhouse.io/v1/boards/{slug}/jobs?content=true` | `api.lever.co/v0/postings/{slug}?mode=json` |
| 字段映射 | title/absolute_url/location.name/content(HTML→md) | text/hostedUrl/categories.location/descriptionPlain |
| 注意 | content 是 HTML,用 html2text 转 md | createdAt 毫秒时间戳 |

- 并发:`asyncio.Semaphore(5)`;429/5xx → 指数退避(2s×2^n,3 次)
- 去重:先 `id` 精确;再同公司内 rapidfuzz `token_sort_ratio(title) > 92` 视为重复,保留 newest
- `sources.yaml`:`[{slug: stripe, source: greenhouse, name: Stripe}, ...]`,首批 30 家(官方 skills 仓库 examples 可参考,SimplifyJobs 清单可辅助选公司)
- 测试:respx 录制两平台真实响应样本(golden file);失败源降级跳过并记日志

## 5. agents(crewAI 装配)

### 5.1 Rubric v1(`agents/prompts.py` 常量,`RUBRIC_VERSION = "v1.0"`)

| 维度 | 权重 | 9-10 分锚点 | 0-2 分锚点 |
|---|---|---|---|
| skills 匹配 | 0.40 | 全部核心技能命中且有加分项 | 核心技能缺 ≥2 项 |
| experience 相关 | 0.25 | 年限/领域双命中 | 完全无关领域 |
| constraints 硬约束 | 0.20 | 地点/远程/薪资全部满足 | 有不可满足项(如需到岗城市不符) |
| growth 成长性 | 0.15 | 明确的技术栈成长路径 | 无相关信息 |

Prompt 模板要点:系统消息声明角色(资深技术招聘顾问)+ rubric 全文 + 锚点 + few-shot 1 例;用户消息 = `{resume_md}(版本 {resume_version})+ {jd_md}`;**要求 evidence.quote 必须逐字来自 JD,否则整条重试**。

### 5.2 Crew(M2,sequential process)

| Agent | 职责 | 工具 | LLM? |
|---|---|---|---|
| Scout | 遍历 sources 调 collector 工具,产出新 JobPosting 列表 | `collect_source(slug)` | 无(LLM 仅汇总) |
| Parser | JD 清洗:规则剥样板(正则表见下)→ gateway 结构化抽取技能/薪资/级别 | — | 规则为主,LLM 补充 |
| Matcher | 简历×JD → MatchScore(gateway.json_in) | — | 是,核心 |
| Reporter | 汇总 scores → 周报(报告模板) | — | 是,综合 |
| Researcher(Should) | `research_company()` 包装 gpt-researcher;GPTResearcher 检索器:ddgs 主、tavily 兜底 | — | 是 |

规则前置清洗样板正则(初版):`(薪资面议|福利待遇|五险一金|公司福利|任职要求[:：]?$|Job Description)` 等段落标记——**清洗只删不改写**,清洗前后 md 都落库。

## 6. storage(SQLite DDL,WAL)

```sql
CREATE TABLE companies(id INTEGER PRIMARY KEY, slug TEXT, source TEXT,
  display_name TEXT, active INTEGER DEFAULT 1);
CREATE TABLE jobs(id TEXT PRIMARY KEY, company_id INTEGER REFERENCES companies,
  title TEXT, location TEXT, remote INTEGER, url TEXT, department TEXT,
  description_raw_md TEXT, description_clean_md TEXT,
  fingerprint TEXT, first_seen TEXT, last_seen TEXT, status TEXT);
CREATE INDEX idx_jobs_status ON jobs(status);
CREATE INDEX idx_jobs_fp ON jobs(fingerprint);
CREATE TABLE scores(id INTEGER PRIMARY KEY AUTOINCREMENT, job_id TEXT REFERENCES jobs,
  overall REAL, dims_json TEXT, evidence_json TEXT, confidence REAL, summary TEXT,
  rubric_version TEXT, model_version TEXT, resume_version TEXT,
  review_status TEXT DEFAULT 'auto', human_overall REAL, created_at TEXT);
CREATE TABLE llm_cache(key TEXT PRIMARY KEY, value_json TEXT, created_at TEXT);
CREATE TABLE usage(ts TEXT, module TEXT, model TEXT, prompt_tokens INTEGER,
  completion_tokens INTEGER, cost_cny REAL, cache_hit INTEGER);
CREATE TABLE annotations(id INTEGER PRIMARY KEY AUTOINCREMENT, job_id TEXT,
  human_overall REAL, dims_json TEXT, annotator TEXT, created_at TEXT);
CREATE TABLE reports(id INTEGER PRIMARY KEY AUTOINCREMENT, period TEXT,
  path TEXT, cost_cny REAL, created_at TEXT);
```

`repo.py` 提供 `JobRepo / ScoreRepo / UsageRepo / AnnotationRepo`;低置信度(<0.6)或双次评分分差>2 → `review_status='review'`。

## 8. scheduler(APScheduler 3.x)

| 任务 | 触发 | 内容 |
|---|---|---|
| 周全量 | 周五 21:00(错峰) | 全源采集 → 解析 → 评分 → 周报 → 通知 |
| 日增量 | 每日 07:30 | 采集 → 仅对 `first_seen=今日` 评分 → 有新高分(≥75)即推送 |
| 预算巡检 | 每日 08:00 | budget_check,超限通知并暂停批处理 |

## 9. eval(评测台,M3)

- `eval/dataset.yaml`:50 条 JD(目标公司抽样),`annotations` 表录 2-3 人打分取均值
- `metrics.py`:spearmanr(scipy.stats)、Top-10 集合重合率、校准分箱(预测分 vs 采纳率)、自一致性(同 JD 评 3 次分差 ≤1 占比)
- `run.py`:任意 prompt/rubric 改动后跑回归,输出 `docs/eval-report.md`;退化即回滚

## 10. app

- CLI(typer):`jobpilot crawl` / `score [--limit N]` / `report` / `eval run` / `budget`
- dashboard(streamlit,M3):周报视图 + 复核队列(人工分回写 annotations)

## 11. 测试与错误处理矩阵

| 故障 | 处理 | 测试方式 |
|---|---|---|
| ATS 429/超时 | 退避 3 次后跳过该源,job 不受影响 | respx 模拟 |
| Schema 校验 3 次失败 | job.status=error, evidence 落日志 | stub LLM |
| 网关超时 | 重试→失败则该 job 记 error,批处理继续 | stub |
| 预算超限 | BudgetExceeded → 停批 + apprise 通知 | 单测 |
| 重复职位 | fingerprint 撞 → 更新 last_seen 不重建 | 单测 |
| browser-use 失败(二期) | 标记该源本次跳过 | — |

CI(GitHub Actions):ruff + pytest(mock 全量,live 默认 skip)。
