# OfferRadar 用户使用手册

> 版本: v1.0 (2026-09-07)
> 适用对象: 计算机专业学生（求职/实习/校招）

---

## 一、系统简介

OfferRadar 是一个多 Agent 求职调研助手，帮助你：

1. **自动采集职位** - 从 Greenhouse/Lever 等平台自动获取目标公司的职位信息
2. **智能匹配评分** - 基于你的简历，对每个职位进行多维度匹配评分
3. **证据链提取** - 从简历中提取可验证声明，与 JD 要求进行匹配
4. **简历优化建议** - 针对高分职位，给出具体的简历修改建议
5. **面试准备** - 自动生成面试预测问题和准备材料
6. **定期周报** - 每周生成求职周报，汇总最值得投的职位

**核心原则**: 只辅助决策，不自动投递，不爬取 LinkedIn。

## 三、安装步骤

### 3.1 Windows 安装

```bash
# 1. 创建虚拟环境
py -3.12 -m venv .venv

# 2. 激活虚拟环境
.venv\Scripts\activate

# 3. 安装依赖
pip install -e ".[dev,m2,m3]"

# 4. 复制配置文件
copy .env.example .env
copy profile.example.yaml profile.yaml
```

### 3.2 macOS / Linux 安装

```bash
# 1. 创建虚拟环境
python3.12 -m venv .venv

# 2. 激活虚拟环境
source .venv/bin/activate

# 3. 安装依赖
pip install -e ".[dev,m2,m3]"

# 4. 复制配置文件
cp .env.example .env
cp profile.example.yaml profile.yaml
```

### 3.3 Docker 安装（推荐）

```bash
# 1. 克隆仓库
git clone https://github.com/your-username/offer-radar.git
cd offer-radar

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env 文件，填入 API Key

# 3. 配置个人信息
cp profile.example.yaml profile.yaml
# 编辑 profile.yaml 文件，填入你的简历信息

# 4. 启动服务
docker-compose up -d

# 5. 访问面板
# 浏览器打开 http://localhost:8501
```

## 六、扩展技能使用

### 6.1 Claim Evidence Extractor（证据链提取器）

**功能**: 从简历中提取可验证声明，与 JD 要求进行匹配，识别差距。

**使用方法**:

```python
from jobpilot.tools.claim_extractor import ClaimExtractor

# 初始化
extractor = ClaimExtractor(gateway, storage)

# 提取 Claim
result = extractor.extract(
    resume_text="负责后端开发，将 API 响应时间从 2s 优化到 200ms",
    jd_text="要求有性能优化经验，熟悉 Kubernetes",
    parsed_jd={"skills": ["Python", "Kubernetes"]},
    resume_version="v1.0",
    job_id="job_001",
)

# 查看结果
print(f"提取到 {len(result.claims)} 个 Claim:")
for claim in result.claims:
    print(f"  - [{claim.claim_type}] {claim.claim_text} ({claim.strength})")

print(f"识别到 {len(result.gaps)} 个 Gap:")
for gap in result.gaps:
    print(f"  - [{gap.gap_type}] {gap.jd_requirement}")
    if gap.mitigation:
        print(f"    建议: {gap.mitigation}")
```

**输出示例**:

```
提取到 2 个 Claim:
  - [Metric] 将 API 响应时间从 2s 优化到 200ms (strong)
  - [Technical] 使用 Python 和 Redis (strong)

识别到 1 个 Gap:
  - [soft_gap] 熟悉 Kubernetes
    建议: 补充 K8s 相关项目经验
```

**Claim 分类说明**:

| 类型 | 说明 | 示例 |
|------|------|------|
| Ownership | 个人负责/主导 | "负责后端开发"、"主导架构设计" |
| Metric | 可量化指标 | "性能提升 50%"、"QPS 达到 10 万" |
| Technical | 技术能力/工具 | "使用 Python"、"熟悉 Redis" |
| Architecture | 系统设计/架构 | "设计微服务架构"、"搭建 CI/CD" |
| Result | 成果/影响 | "上架 App Store"、"节省成本 10 万" |

**证据强度说明**:

| 强度 | 说明 |
|------|------|
| strong | 有具体数字、明确成果、可验证 |
| weak | 模糊表述（如"熟练掌握"）、缺乏细节 |
| missing | 简历中无相关证据 |

### 6.2 Gap Advisor（简历差距顾问）

**功能**: 针对高分但证据不足的职位，生成具体的简历修改建议和 HR 开场白。

**使用方法**:

```python
from jobpilot.tools.gap_advisor import GapAdvisor

# 初始化
advisor = GapAdvisor(gateway, storage)

# 生成简历补丁
patch = advisor.generate_patch(
    resume_text="负责后端开发，使用 Python 和 Redis",
    job_posting_summary="要求有后端开发经验，熟悉 Kubernetes",
    claims=[...],  # 从 Claim Extractor 获取
    gaps=[...],    # 从 Claim Extractor 获取
    job_id="job_001",
)

# 查看改写建议
print("改写建议:")
for rewrite in patch.bullet_rewrites:
    print(f"  原文: {rewrite.original_text}")
    print(f"  建议: {rewrite.suggested_rewrite}")
    print()

# 查看 HR 开场白
if patch.hr_opener:
    print(f"HR 开场白:\n{patch.hr_opener.opener_text}")

# 查看完整补丁
print(f"\n可合并的增量内容:\n{patch.patch_markdown}")
```

**输出示例**:

```
改写建议:
  原文: 负责后端开发
  建议: 主导后端 API 设计与开发，优化接口性能提升 10 倍

HR 开场白:
我是一名有丰富后端开发经验的工程师，主导过多个高并发系统的设计与优化。
在最近的项目中，我将 API 响应时间从 2s 优化到 200ms，性能提升 10 倍。
我熟练掌握 Python 和 Redis，能够快速构建高性能的后端服务。
```

### 6.3 Interview Prep Generator（面试预测器）

**功能**: 高分职位自动生成面试准备材料。

**使用方法**:

```python
from jobpilot.tools.interview_prep import InterviewPrep

# 初始化
prep = InterviewPrep(gateway, storage)

# 生成面试速览
brief = prep.generate_brief(
    job_posting_summary="要求熟悉 Python 和微服务",
    company_research="这是一家专注于云计算的公司...",
    claims=[...],  # 从 Claim Extractor 获取
    gaps=[...],    # 从 Claim Extractor 获取
    resume_text="负责后端开发",
    job_id="job_001",
)

# 查看预测问题
print("预测面试问题:")
for q in brief.predicted_questions[:5]:
    print(f"  - {q.question_text} (概率: {q.probability:.0%})")

# 查看追问协议
print("\n追问协议:")
for f in brief.followup_protocol[:3]:
    print(f"  问题: {f.followup_text}")
    print(f"  检测: {f.detection_target}")
    print(f"  危险信号: {', '.join(f.red_flags)}")
    print()

# 查看弱项练习
print("弱项练习:")
for d in brief.weak_area_drills:
    print(f"  - {d.drill_questions[0]}")
    print(f"    期望: {d.expected_evidence}")
    print()

# 查看完整面试速览
print(f"面试速览:\n{brief.brief_markdown}")
```

**输出示例**:

```
预测面试问题:
  - 请介绍你的性能优化经验 (概率: 90%)
  - Python 的 GIL 是什么？如何绕过？ (概率: 75%)
  - 如何设计一个高并发系统？ (概率: 70%)

追问协议:
  问题: 这个性能优化是你独立完成的吗？
  检测: 验证 Ownership
  危险信号: 用"我们"代替"我"、避重就轻

  问题: 200ms 这个数字是怎么测出来的？
  检测: 验证 Metric 真实性
  危险信号: 说不出具体测试方法、含糊其辞

弱项练习:
  - 请介绍 Kubernetes 的核心概念
    期望: 能说出 Pod、Service、Deployment 等核心概念
```

## 九、常见问题

### 9.1 API 相关

**Q: API 调用失败怎么办？**

A: 检查以下几点：
1. API Key 是否正确配置在 `.env` 文件中
2. API 余额是否充足
3. 网络是否能访问 API 端点
4. 查看 `logs/` 目录下的日志文件

**Q: 如何降低 API 成本？**

A: 系统已内置成本优化：
1. 结果缓存 - 相同 JD + 简历不会重复调用
2. 错峰调度 - 非高峰时段调用更便宜
3. 批量处理 - 一次调用处理多条 JD
4. 预算控制 - 月度超限自动停止

### 9.2 评分相关

**Q: 评分结果不准确怎么办？**

A: 可以通过以下方式优化：
1. 完善 `profile.yaml` 中的简历内容
2. 确保简历包含具体的项目经历和成果
3. 使用 Claim Extractor 查看证据链，针对性优化

**Q: 如何提高匹配分数？**

A: 根据 Gap 分析结果：
1. 补充缺失的技能经历
2. 量化已有经历（如"性能提升 50%"）
3. 针对目标职位调整简历重点

### 9.3 部署相关

**Q: Docker 部署失败怎么办？**

A: 检查以下几点：
1. Docker 是否正确安装
2. `.env` 文件是否配置正确
3. 端口 8501 是否被占用
4. 查看 Docker 日志: `docker-compose logs`

**Q: 如何更新系统？**

A:
```bash
# 拉取最新代码
git pull

# 重新构建并启动
docker-compose down
docker-compose up -d --build
```
