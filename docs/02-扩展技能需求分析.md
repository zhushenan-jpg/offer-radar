# OfferRadar 扩展技能需求分析

> 三个 MVP 扩展技能：Claim Evidence Extractor / Resume Gap Advisor / Interview Prep Generator
> 文档版本:v1.0(2026-09-07) · 状态:待确认,确认后进入概要设计
> 前置依赖:01-需求分析与概要设计.md 中 FR1-FR10 已定义

---

## 一、扩展背景

### 1.1 现有能力（来自 01 文档）

| Agent | 职责 | 输出 |
|-------|------|------|
| Scout | 职位采集 | JobPosting[] |
| Parser | JD 结构化解析 | 技能/级别/薪资/地点/远程标记 |
| Matcher | 匹配评分 | MatchScore(overall + dims + evidence + confidence) |
| Reporter | 周报生成 | Markdown/HTML 周报 |

### 1.2 现有不足

当前流水线止步于"发现匹配职位 + 给出分数"，用户拿到周报后仍需：
1. 手动分析"为什么这个分"——evidence 字段只有 quote/span，缺乏结构化 Claim 分类
2. 手动判断"简历哪里要改"——FR10 仅标记为 Could，无具体产出
3. 手动准备面试——系统不提供面试预测和练习

### 1.3 扩展目标

**从"发现机会"到"抓住机会"的闭环**：评分 → 证据链 → 简历优化 → 面试准备，形成完整求职辅助链路。

## 二、技能 1：Claim Evidence Extractor（证据链提取器）

### 2.1 定位

增强 Matcher Agent 的评分输出，从"给分"升级为"给分 + 结构化证据链"。

### 2.2 用户故事

| 编号 | 故事 | 验收标准 |
|------|------|----------|
| US-CE-1 | 作为求职学生，我希望看到每条评分背后的具体证据，而不是一个笼统的分数 | MatchScore.evidence 包含 claim_type、claim_text、jd_evidence、strength、gap 字段 |
| US-CE-2 | 作为求职学生，我希望能区分"硬性门槛不满足"和"软性差距" | 输出 GapReport 区分 hard_block（如学历不达标）和 soft_gap（如缺少某框架经验） |
| US-CE-3 | 作为求职学生，我希望证据能追溯到简历和 JD 的原文 | 每条 Claim 包含 resume_span 和 jd_span，可定位原文 |

### 2.3 功能需求

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| FR-CE-1 | Claim 提取 | Must | 从简历文本中提取可验证声明，分类为 Ownership/Metric/Technical/Architecture/Result 五类 |
| FR-CE-2 | Claim-JD 映射 | Must | 将每个 Claim 与 JD 要求进行匹配，输出匹配/缺失/弱证据三种状态 |
| FR-CE-3 | Gap 分类 | Must | 区分 hard_block（必须满足）和 soft_gap（加分项） |
| FR-CE-4 | 证据追溯 | Must | 每条 Claim 和 Gap 包含 resume_span/jd_span 原文引用 |
| FR-CE-5 | 弥补建议 | Should | 对每个 soft_gap 生成一句话弥补建议 |
| FR-CE-6 | 缓存复用 | Should | 同一 JD + 简历版本的 Claim 结果缓存，避免重复提取 |

### 2.4 数据模型扩展

```
Claim {
  id: str
  claim_type: enum[Ownership, Metric, Technical, Architecture, Result]
  claim_text: str           # 声明内容
  resume_span: {start, end, text}  # 简历原文定位
  jd_evidence: str|null     # JD 中对应的证据（如有）
  jd_span: {start, end, text}|null
  strength: enum[strong, weak, missing]  # 证据强度
}

Gap {
  id: str
  gap_type: enum[hard_block, soft_gap]
  jd_requirement: str       # JD 中的要求
  related_claims: Claim[]   # 关联的 Claim（如有）
  mitigation: str|null      # 弥补建议（soft_gap 时）
}

ClaimExtractionResult {
  job_id: str
  resume_version: str
  claims: Claim[]
  gaps: Gap[]
  evidence_matrix: map<claim_id, map<jd_requirement_id, match_status>>
  extraction_cost: {tokens, amount}
  created_at: datetime
}
```

### 2.5 非功能需求

| 指标 | 目标 |
|------|------|
| 成本增幅 | 单条 JD 评分成本增幅 ≤ 20%（Claim 提取复用已有 JD 解析） |
| 延迟增幅 | 单条 JD 评分延迟增幅 ≤ 5 秒 |
| 准确率 | Claim 分类准确率 ≥ 85%（人工抽检 50 条） |
| 缓存命中率 | 二次运行 Claim 提取跳过率 ≥ 90% |

## 三、技能 2：Resume Gap Advisor（简历差距顾问）

### 3.1 定位

针对高分但证据不足的职位，生成具体的简历修改建议和 HR 开场白。

### 3.2 用户故事

| 编号 | 故事 | 验收标准 |
|------|------|----------|
| US-RG-1 | 作为求职学生，我希望系统告诉我简历哪里要改，而不是让我自己猜 | 输出 BulletRewrite[]，每条包含原文、改写建议、匹配的 JD 要求 |
| US-RG-2 | 作为求职学生，我希望能直接复制改写内容到简历 | 输出 ResumePatch.md，格式可直接合并 |
| US-RG-3 | 作为求职学生，我需要针对不同职位的 HR 开场白 | 输出 HROpener，一段话，突出与该职位最相关的经历 |

### 3.3 功能需求

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| FR-RG-1 | Bullet 改写建议 | Must | 基于 Gap 分析，对现有简历经历给出改写建议 |
| FR-RG-2 | 缺失证据建议 | Must | 对 soft_gap 生成需要补充的项目/经历/技能建议 |
| FR-RG-3 | HR 开场白生成 | Must | 针对目标职位的一段话开场白 |
| FR-RG-4 | ResumePatch 输出 | Should | 可直接合并到简历的增量内容（Markdown 格式） |
| FR-RG-5 | 多职位聚合 | Should | 对 Top N 高分职位的 Gap 取并集，生成综合改进建议 |
| FR-RG-6 | 触发条件配置 | Could | 用户可配置"几分以上触发建议生成"（默认 70 分） |

### 3.4 数据模型扩展

```
BulletRewrite {
  id: str
  original_text: str        # 简历原文
  suggested_rewrite: str    # 改写建议
  matched_jd_requirement: str
  claim_id: str             # 关联的 Claim
}

MissingEvidence {
  id: str
  gap_id: str               # 关联的 Gap
  suggested_activity: str   # 建议补充的活动
  priority: enum[high, medium, low]
}

HROpener {
  job_id: str
  opener_text: str          # 一段话开场白
  highlight_claims: Claim[] # 突出的 Claim
}

ResumePatch {
  job_id: str
  bullet_rewrites: BulletRewrite[]
  missing_evidence: MissingEvidence[]
  hr_opener: HROpener
  patch_markdown: str       # 可合并的增量内容
  generation_cost: {tokens, amount}
  created_at: datetime
}
```

### 3.5 非功能需求

| 指标 | 目标 |
|------|------|
| 触发范围 | 仅对 Top N（默认 10）高分职位生成建议，不全量跑 |
| 成本上限 | 单份 ResumePatch 生成成本 ≤ ¥0.05 |
| 延迟 | 单份 ResumePatch 生成 ≤ 10 秒 |
| 可用性 | 改写建议可直接复制使用，无需二次编辑 |

## 四、技能 3：Interview Prep Generator（面试预测器）

### 4.1 定位

评分后的自然延伸——高分职位自动生成面试准备材料。

### 4.2 用户故事

| 编号 | 故事 | 验收标准 |
|------|------|----------|
| US-IP-1 | 作为求职学生，我希望能预测面试会问什么 | 输出 PredictedQuestions[]，按 Claim 类型分类 |
| US-IP-2 | 作为求职学生，我希望能练习追问 | 输出 FollowUpProtocol，每个问题有追问策略 |
| US-IP-3 | 作为求职学生，我需要针对弱项的专项练习 | 输出 WeakAreaDrill[]，针对 evidence 薄弱的 Claim |
| US-IP-4 | 作为求职学生，我需要一页纸面试速览 | 输出 InterviewBrief.md，包含公司背景+技术栈+预测题+我的证据 |

### 4.3 功能需求

| 编号 | 需求 | 优先级 | 说明 |
|------|------|--------|------|
| FR-IP-1 | 问题预测 | Must | 基于 JD + Claim 生成高频面试问题，按 Claim 类型分类 |
| FR-IP-2 | 追问协议 | Must | 每个问题生成 2-3 个追问，检测 Claim 真实性 |
| FR-IP-3 | 弱项练习 | Must | 对 strength=weak/missing 的 Claim 生成专项练习题 |
| FR-IP-4 | 面试速览 | Must | 一页纸 Markdown：公司背景+技术栈+预测题+证据摘要 |
| FR-IP-5 | 公司调研集成 | Should | 复用 Researcher Agent 的公司调研报告 |
| FR-IP-6 | 练习模式 | Could | 用户可交互式回答问题，系统给出反馈（二期） |

### 4.4 数据模型扩展

```
PredictedQuestion {
  id: str
  question_text: str
  claim_type: enum[Ownership, Metric, Technical, Architecture, Result]
  related_claims: Claim[]
  probability: float[0,1]   # 预测概率
  source: enum[jd_direct, jd_inferred, company_culture]
}

FollowUp {
  question_id: str
  followup_text: str
  detection_target: str     # 检测什么（如"指标真实性"、"个人贡献度"）
  red_flags: str[]          # 危险信号（如"说不出具体数字"、"用'我们'代替'我'"）
}

WeakAreaDrill {
  id: str
  target_claim: Claim
  drill_questions: str[]    # 练习题
  expected_evidence: str    # 期望的回答证据
  common_mistakes: str[]    # 常见错误
}

InterviewBrief {
  job_id: str
  company_overview: str     # 来自 Researcher Agent
  tech_stack: str[]         # 来自 JD 解析
  predicted_questions: PredictedQuestion[]
  followup_protocol: FollowUp[]
  weak_area_drills: WeakAreaDrill[]
  evidence_summary: map<claim_type, Claim[]>
  brief_markdown: str       # 一页纸速览
  generation_cost: {tokens, amount}
  created_at: datetime
}
```

### 4.5 非功能需求

| 指标 | 目标 |
|------|------|
| 触发范围 | 仅对 Top N（默认 5）高分职位生成面试准备 |
| 成本上限 | 单份 InterviewBrief 生成成本 ≤ ¥0.10 |
| 延迟 | 单份 InterviewBrief 生成 ≤ 30 秒（含公司调研） |
| 问题覆盖 | 预测问题覆盖 ≥ 80% 的 JD 明确要求 |

## 五、整体约束

### 5.1 架构约束（来自 01 文档）

- **不新增独立流水线**：三个技能嵌入现有 Agent，不增加系统复杂度
- **复用已有数据**：Claim 提取复用 Matcher 的 JD 解析结果，面试预测复用 Researcher 的公司调研
- **渐进式增强**：M1-M4 不变，这些作为 M5+ 的增量
- **成本可控**：面试预测只对 Top N 高分职位触发，不全量跑

### 5.2 与现有 Agent 的集成方式

| 技能 | 集成方式 | 理由 |
|------|----------|------|
| Claim Evidence Extractor | 嵌入 Matcher Agent 的 prompt | 提取是评分的自然副产物 |
| Resume Gap Advisor | 嵌入 Reporter Agent 的周报生成流程 | 建议是周报的"行动建议"章节 |
| Interview Prep Generator | 新增 Interviewer Agent（或 Reporter 子任务） | 面试准备需要独立的交互模式 |

### 5.3 成本预算增量

| 技能 | 单次成本 | 触发频率 | 月增量预算 |
|------|----------|----------|------------|
| Claim Extractor | ≤ ¥0.005/条 | 每条 JD | ≤ ¥5（1000 条/月） |
| Gap Advisor | ≤ ¥0.05/份 | Top 10/周 | ≤ ¥2（4 周） |
| Interview Prep | ≤ ¥0.10/份 | Top 5/周 | ≤ ¥2（4 周） |
| **合计** | | | **≤ ¥9/月** |

### 5.4 里程碑规划

| 阶段 | 内容 | 出口标准 | 依赖 |
|------|------|----------|------|
| M5（第 5 周） | Claim Evidence Extractor | MatchScore.evidence 结构化输出 + 50 条人工评测 | M2 完成 |
| M6（第 6 周） | Resume Gap Advisor | Top 10 职位自动生成 ResumePatch | M5 完成 |
| M7（第 7 周） | Interview Prep Generator | Top 5 职位自动生成 InterviewBrief | M5 + M6 完成 |
